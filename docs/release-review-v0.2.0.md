# v0.2.0 发布前检查

检查日期：2026-11-05。范围：应用启动与单实例、快捷键与资源管理器 COM、预览加载与关闭、搜索和设置、索引与图标、打包与依赖。已检查现有源文件和本次新增文件；最终版本未保留已知 P0/P1 阻断项。

## 发现与修复

| 等级 | 问题 | 最终处理 |
| --- | --- | --- |
| P1 | 关闭窗口触发原生失焦事件，再次 Close 导致进程退出 | 在 Closing 阶段标记状态；统一幂等关闭入口；延迟处理正常失焦；缓存原生句柄 |
| P1 | 极端宽高图片、PDF 可能产生巨大解码缓冲区 | 图片限制在 2400×2400 内，PDF 限制在 1600×2200 内，保持比例并拒绝无效尺寸 |
| P1 | 重复系统查询与慢文件读取可能积累工作线程或阻塞界面 | 系统查询限制为一个后台 STA 请求，等待上限 3 秒；同时最多两次加载；元数据、读取、图片解码放到后台 |
| P1 | 异常或手动修改的设置可能在启动时触发重复键错误 | 合并大小写重复键、清理空路径、限制计数和别名，并限制设置文件大小 |
| P2 | 原生键盘回调的异常可越过进程边界；退出等待可能无限阻塞 | 回调捕获可恢复异常、停止失败的预览监听；启动始终发出完成信号；退出等待有界、重复释放安全 |
| P2 | 清理异步操作的异常缺少统一观察，关闭非视频预览也调用播放器 | 观察清理任务；只清理已设置来源的视频；先等待取消中的 PDF 操作，再释放输入流 |
| P2 | 异常 Office 压缩内容和无界错误日志可能消耗资源 | 限制文件/分项/解压字符数量、禁止外部实体；错误日志轮换并限制单条长度 |

保留 WPF 窗口、预览服务、键盘监听、文件选择和纯内容处理的职责边界；没有新增插件系统或全盘扫描。未发现需要另行迁移的删除项。

## 验证

- Release 模式 74 项检查通过；包括真实 Windows PDF 渲染、超宽/超长图片解码、错误文件、加载中关闭、关闭重入及文件句柄释放。
- 1,000 次隐藏组件预览压力检查通过：28.97 秒，最终句柄相对暖机后增加 42，托管内存相对暖机后增加约 22 KB，均低于检查阈值；该结果不代表桌面端到端唤出耗时。
- 2000 条应用、200 次搜索：平均约 1.30 ms/次，不包含界面、磁盘扫描或启动。
- `dotnet list Glint.slnx package --vulnerable --include-transitive` 未报告已知漏洞。
- 可分发包包含应用、.NET 运行时、Windows Runtime 投影、使用说明、源提交与第三方授权，发布附件需核对 SHA256。

## 未覆盖与后续

此检查不保证所有设备永不崩溃。多屏混合 DPI、Windows 11 多标签资源管理器、更多中文输入法、第三方视频解码器及长期系统休眠/恢复仍需实机覆盖。损坏文件不能绕过系统解码器自身的原生缺陷；这类问题应结合本地日志与 Windows 错误记录定位。当前 Office 内容以文字方式预览，不处理宏或嵌入对象，不承诺完整排版。
